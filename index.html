CASE 01 / 智能与策略判断

围棋对弈：理解局面，权衡下一步

Fold-X Flash 执白，与 DeepSeek 执黑进行 19×19 围棋对弈。通过连续落子，展示对局面、候选选择与后续影响的判断。

起点是策略判断：在明确规则下理解当前局面，并选择行动。

应用价值 · 适用于需要比较候选方案、权衡局部得失与后续影响的决策任务。

观察结果与证据边界
  • 结束界面的估分显示白方领先 80.5；对手具体版本未提供。
  • 视频保留原始对弈顺序，聚焦棋盘与计分。

速度口径 · 5 倍速用于缩短观看时间，不代表模型响应速度。

这是单局演示的界面估分，未经独立裁判核验，不等于多局胜率或综合智力评测。

CASE 02 / 快速准确的行动决策

超级玛丽：在变化中及时行动

面对移动的敌人、变化的地形与有限的行动时机，Fold-X 根据当前游戏状态持续选择前进、跳跃或等待。左侧看行动效果，右侧看当时的状态、所选动作与候选分数。

从策略选择进一步走向时机把握：环境持续变化，判断需要及时转化为有效动作。

应用价值 · 适用于游戏智能体、交互应用与需要连续反馈的行动选择。

观察结果与证据边界
  • 录屏包含多个关卡的连续行动，结束于 4-3 关卡。
  • 右侧面板是状态与决策摘要；候选分数不是实测准确率或通关概率。

速度口径 · 全段 5 倍速；真实请求耗时应按运行记录统计，不能从播放速度推算。

演示用于观察行动时机与效果，未统计多次运行成功率，不表示全游戏通关，也不据此声称仅靠原始像素控制。

CASE 03 / 复杂环境中的连续决策

机器人快递员：结合多种因素调整行动

在 Unreal Engine（UE）派送仿真中，为机器人设定目标，环境要素、行人与车辆随机投放。Fold-X 根据当下的外界信息，持续决定前进、等待或调整行动。

从游戏中的行动时机，推进到多因素判断：目标、行人、车辆、信号与通行条件需要一起考虑。

应用价值 · 探索机器人与世界交互的一种方式：围绕目标观察变化，作出反馈，并随新状态继续调整。

观察结果与证据边界
  • 按项目资料，使用宇树 G9 虚拟机器人模型；该名称为项目资料标识。
  • 演示包含绿灯剩余时间不足时等待、红灯时停在路缘，以及随后继续行进。
  • 项目方说明未针对该派送场景与路线进行专项预训练；这不意味着基础模型从未训练。

速度口径 · 保留原始播放速度；录像时长不是单次决策延迟。

当前是 UE 仿真，未证明在实体机器人上部署、完成整段派送或达到真人行为水平。

CASE 04 / 多个决策点的协同

交通信号调度：持续协调 62 个路口

Fold-X 根据仿真中不断更新的车流，参与 62 个路口的信号决策。一个路口的放行会影响后续路段，局部选择需要放到整个路网中观察。

从一个行动主体推进到多个相互影响的节点：各路口既有局部需求，也共同影响路网运行。

应用价值 · 适用于多节点调度、资源分配与持续协调场景的功能探索。

观察结果与证据边界
  • 展示 62 个路口随仿真路况变化持续作出选择。
  • 界面将本轮标记为“无效对照”，不据此报告交通效率提升。

速度口径 · 录屏未额外加速；原应用回放显示 16 倍速，不能据此推算实际决策吞吐。

这是动态仿真与回放，不代表真实城市部署、全局最优，也不证明单次 API 调用完成全部 62 个路口的判断。

CASE 05 / 自然语言理解画面

画面监控与视频搜索：说出条件，找到画面

用自然语言描述目标、行为或组合条件，Fold-X 判断画面是否匹配。监控应用记录命中画面；视频搜索返回候选缩略图与时间位置，便于跳转回看。

进入视觉理解：把用户用语言表达的目标，与画面中的具体内容对应起来。

应用价值 · 适用于监控事件筛选、视频内容检索与自然语言条件抓拍。

观察结果与证据边界
  • 演示包含多条件判断、关注区域、命中记录和视频时间跳转。
  • 监控画面使用素材回放；候选匹配分数不等于标注数据上的准确率。

速度口径 · 项目资料称画面判断环节可达毫秒级；本次未独立核验，不等于毫秒内搜索完整视频或云端 API 延迟承诺。

附件展示功能流程，未提供完整准确率评测或可复算的单次延迟分布。

CASE 06 / 以图理解、识别与判断

参考图片检索：从参考图找到相关画面

用一张参考图片表达要找的内容，再在图片集合与视频画面中比较、识别和判断。应用展示候选、分数与对应的视频时间位置。

从语言描述目标推进到图片表达目标：先理解参考图，再判断其他画面与它的关系。

应用价值 · 适用于视觉素材查找、图片库筛选与视频候选片段定位。

观察结果与证据边界
  • 图片部分为历史结果回放；视频部分结束时扫描到 143 / 735 帧，约 19%，显示 23 个候选。
  • 候选结果仍需回看确认，匹配正确率尚未独立核验。

速度口径 · 一个时点的界面读数为 6.7 帧/秒；它不是全程平均吞吐，也不是单次模型延迟。

这是部分扫描的功能展示，不作为完整检索耗时、准确率或相对其他模型优势的证据。

CASE 07 / 审美理解与细节鉴察

艺术鉴赏与古董观察：从看见细节，到理解美

从绘画与摄影中的线条、色彩、构图和空间关系出发，尝试解释画面氛围；把细致观察延伸到器物图片，整理可见线索与需要继续核验的问题。

从识别和比较推进到关系解读：观察细节如何共同形成视觉感受，以及它们能够支持怎样的初步判断。

应用价值 · 初步探索艺术观看辅助、作品解读、藏品记录与鉴定前的线索整理。

观察结果与证据边界
  • 艺术演示将街景中的道路双黄线、山谷、建筑与色彩联系起来，形成氛围解读。
  • 器物报告保留“碗／杯形尚待区分”等不确定性，提出补拍裂纹与接合处的建议。
  • 古董界面标注综合报告由“LLM 整理”，呈现的是接入 Fold-X 的应用整体输出，不将全部报告文字归因为 Fold-X 单独生成。

速度口径 · 两段视频保留原速；录屏长度不代表单次判断或整份报告的生成延迟。

初步展现艺术鉴赏的应用表现，未经专业能力评测；图片观察不能确认古董真伪、年代、材质或市场价值。

常见问题

Fold-X 是什么？

一个多模态决策模型，面向文字与图像中的判断、选择和评分任务，目标是让决策更准、更快、更省。当前可通过 Flash-1.3 API 接入。

哪些任务适合先试？

分类、条件判断、候选选择、评分与图像条件筛选。先选有明确输入、输出和验收标准的任务，用代表性样本验证。

七个演示可以直接通过 API 运行吗？

API 提供判断能力；视频搜索、游戏、机器人和交通应用还需要取帧、环境连接、动作执行等配套集成。演示并不等于完整应用已作为标准服务交付。

中文支持体现在哪里？

覆盖中文词义、句间关系、多义表达和修辞判断。Flash 深度配置在 C-SEM 公开集四项共1,200题的团队自测中，宏平均为93.33%；不等于所有中文任务的准确率。

“准、快、省”是对所有任务的保证吗？

是产品追求，并非无条件保证。准确性看具体任务；速度区分模型耗时与端到端API耗时；费用按完整任务计算。案例与评测页逐项说明测试条件和边界。

返回的分数就是正确概率吗？

不是。分数用于比较候选或设置筛选阈值，不能直接视为真实正确率。上线前应在自己的业务数据上验证，必要时设置人工复核。

如何调用、计费和申请试用？

通过HTTPS文字或图像接口调用。当前支持计点和计时授权，价格与额度在开通时确认。联系两位创始人申请试用，普通产品问题也可在GitHub Issues留言。

会公开代码、权重或客户资料吗？

本仓库只展示产品能力、评测摘要和应用素材，不发布核心实现、模型权重、密钥或客户原始数据。企业资料与数据处理要求通过非公开渠道另行确认。
