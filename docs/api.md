# API 接入与能力范围

[English](../en/docs/api.md) · [返回首页](../README.md)

Fold-X 是多模态决策模型。目前已提供 **Fold-X Flash-1.3 文字决策与图像条件判断 API**，通过 HTTPS 调用。Light、Pro 的接入安排请联系团队确认，不把基准中的模型版本等同于当前在线服务。

## 当前可调用的能力

| 服务 | 输入 | 返回 | 单次请求范围 |
|---|---|---|---|
| 文字决策 | 文字或结构化材料、问题、候选项 | 选择结果、评分档位或条件分数 | 1–256 道独立问题 |
| 图像条件判断 | 一张图片、自然语言条件 | 匹配结果、匹配分数及阈值判断 | 单条件，或 1–64 条条件 |
| 余额查询 | 已授权的密钥 | 剩余点数或天数 | 查询不扣点 |

视频搜索、游戏、机器人和交通演示由应用配合 Fold-X 完成。视频取帧、动作执行、环境连接与结果展示需要配套集成；这些演示不表示 API 能直接接管完整应用。

## 开始试用

1. [联系团队](contact.md)，说明任务、预计调用量和关注的质量、时延或费用目标。
2. 获取服务地址、对应服务密钥与使用额度。
3. 先用少量代表性数据检查输入输出，再进行批量测试。

请求头使用 `Authorization: Bearer YOUR_API_KEY`。密钥只保存在自己的服务端或安全环境变量中，不放进公开仓库或网页。本文不附带真实密钥；服务地址随试用开通提供。

## 接口与输出

| 接口 | 用途 |
|---|---|
| POST /v1/systemone | 文字决策 |
| POST /v1/systemone/stream | 文字决策与 SSE 进度 |
| POST /v1/image/classify | 图像条件判断 |
| POST /v1/image/classify/stream | 图像判断与 SSE 进度 |
| POST /v1/key/balance | 查询额度 |

文字请求提供 `state` 与 `questions`。`choice` 返回选项 ID，`score` 返回评分档位索引，`noul` 返回条件成立分数。`review_mode` 可选择 `standard` 或 `adaptive`；具体选用应在自己的业务样本上比较。

图像请求提供 `image_base64`，以及 `description` 或 `questions` 二者之一。`matches` 是模型判断，`threshold_match` 表示分数是否达到设定阈值，两者可能不同。图像分数及候选分数不应直接解释成经业务验证的准确率。

## 输入与运行边界

- 文字请求 JSON 最大 4 MiB；文档规定每题上下文、问题和候选等合计上限为 262,144 tokens。实际耗时与可用容量取决于内容及负载。
- 图片支持 JPEG、PNG、WebP；原文件不超过 1 MiB，宽高各为 32–8192 像素，总像素不超过 2,500 万；请求 JSON 最大 12 MiB。
- 服务繁忙返回 503 时，按 `Retry-After` 等待并降低并发。429 表示额度不足，不应盲目自动重试。401 时检查密钥，422 时修正输入。
- 选择题结果、匹配分数或演示读数都不能代替自己业务上的准确率与延迟验证。

## 计费与耗时口径

当前手册支持计点及计时授权。计点文字请求按“问题数 × 正文 UTF-8 字节数对应的计费单位”结算，每题至少 1 点；具体规则为 max(1, 正文字节数 / 1024 四舍五入)。问题与选项不计入正文字节，结构化正文按紧凑 JSON 计算。图像按成功判断的条件数扣点。输入错误或处理失败不扣点，服务繁忙被拒绝不扣点。实际价格与额度在开通时确认，不沿用旧测试报价。

评估 API 速度时，优先记录客户端发出请求至收到完整结果的端到端耗时。图像返回的 `inference_seconds` 与 `elapsed_seconds` 是服务内计时，其中后者不含上传和图像解码，不能直接作为完整 API 延迟。
